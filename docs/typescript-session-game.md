# Этап №8: завершение миграции ядра

12 октября 2026 года. Последовательно переведены `src/application/session.js` → `session.ts` и `src/application/game.js` → `game.ts`. Теперь все 11 модулей ядра `domain/application` имеют настоящие TS-исходники. Технический `build-smoke.ts` не является игровым модулем. Адаптеры и bootstrap остаются JavaScript.

## Изменения

- Существующая сборка генерирует `dist/application/session.js` и `dist/application/game.js` как classic scripts. Регистрация через `globalThis.TBS` и публичные API сохранены, runtime import/export нет.
- В `index.html` заменены ровно два пути относительно состояния перед этапом №8; порядок подключения не изменён.
- JSDoc-типы `SessionOptions`, `GameSession`, `PhysicsEvent`, `FrameUpdate`, `BrakingState`, `GameFramePorts`, `GameDependencies`, `GameScenario` перенесены в `types/game-contracts.d.ts`. Состав DI-объектов, методы портов, параметры и типы результатов сохранены, включая `undefined` для состояния торможения. Переиспользуются общие типы состояния и миссий.
- В `tsconfig.contracts.json` заменены два пути. В тестах `application` и `architecture` обновлены только пути загрузки; helper и ожидания тестов не менялись.
- Старые JS-исходники удалены после сохранения копий. Единственные редактируемые реализации — `.ts`, сгенерированный JS не редактировался вручную.
- Обновлены README и текущий статус документации сборки. Инфраструктура, зависимости, графика, физика, транспорт и игровые правила не изменялись. `any`, подавления ошибок и ослабление strict не добавлялись.

## Доказательства совместимости

Исходные и скомпилированные версии выполнялись в независимых VM-контекстах с одинаковыми зависимостями и входами. Полный исполняемый AST обоих модулей совпал после исключения комментариев и координат текста. Проверены ключи API, заморозка объектов, имена и арность функций; примитивные значения сравнивались через `Object.is`, включая знак нуля и `undefined`.

| Проверка                  | Реальный результат                                                                                                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Жизненный цикл сессии     | Девять операций: точное совпадение состояния, аргументов и порядка вызовов при старте, повторном старте, паузе, возобновлении и неактивном режиме                                  |
| Сохранность данных сессии | Идентичность переданных объектов игрока и управления, null-прототип управления, груз, прогресс, скорость и батарея сохранены; сброс часов выполнен пять раз в проверенном сценарии |
| Кадровый сценарий         | 18 кадров в `intro`, `playing`, `paused` и две инициализации: состояния и все вызовы портов совпали; физика вызвана девять раз только в режиме `playing`                           |
| Таймеры и события         | Проверены пороги HUD/миникарты 0,1 с, сохранение таймеров при повторной инициализации, события удара и подзарядки, исходная скорость до физики и `undefined` торможения            |
| Совместный прогон         | 60 кадров с настоящими физикой, трафиком из 36 машин и сессией; 2160 снимков транспорта, состояния игрока, операции сессии и все вызовы адаптеров совпали                          |

При паузе по-прежнему нулевое время получают timeline, мир, маркеры и рендеринг, а пешеходы, автомобиль, камера, освещение и таймеры HUD используют исходный `dt`. В режиме intro физика и симуляция транспорта не запускаются. Инициализация обновляет HUD и миникарту без продвижения времени. Эти особенности сохранены без исправления или переосмысления поведения.
