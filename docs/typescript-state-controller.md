# Этап №7: состояние и управление миссиями

12 октября 2026 года. Последовательно переведены `src/domain/state.js` → `state.ts` и `src/application/mission-controller.js` → `mission-controller.ts`. Теперь на TypeScript девять из 11 проверяемых игровых модулей; `game.js` и `session.js` остаются JavaScript. Технический `build-smoke.ts` не является игровым модулем.

## Изменения

- Использована существующая сборка без изменения инфраструктуры и зависимостей. Результаты: `dist/domain/state.js` и `dist/application/mission-controller.js`, обычные classic scripts с прежней регистрацией в `globalThis.TBS`.
- В `index.html` заменены ровно два пути относительно состояния перед этим этапом; порядок подключения сохранён.
- В `types/game-contracts.d.ts` перенесены прежние JSDoc-типы `GameMode`, `MissionStage`, `ControlsState`, `PlayerState`, `GameState`, `MissionControllerOptions`, `MissionController`. Поля, необязательность управляющих флагов и изменяемость данных сохранены. Общие `PointXZ`, `MissionRoutes`, `MissionInteractionResult`, `MissionSuccess`, `MissionDelivery`, `GameFramePorts` переиспользуются.
- В `tsconfig.contracts.json` заменены два исходных пути. В тестах `application`, `architecture`, `camera`, `input`, `missions`, `physics` обновлены только пути загрузки состояния/контроллера. Helper не потребовал изменений; ожидания тестов сохранены.
- Старые `.js` удалены после сохранения исходных копий. Единственные редактируемые реализации этих модулей — `.ts`; сгенерированный JS не редактировался вручную.
- Обновлены README и текущий статус в `docs/typescript-build.md`.

Утверждения типов в `resetControls` и контроллере соответствуют прежним JSDoc-утверждениям и не добавляют исполняемых проверок. Утверждение `Object.create(null) as ControlsState` описывает прежний словарь с null-прототипом. `any`, подавления ошибок и отключение строгой проверки не добавлялись.

## Подтверждённая эквивалентность

Оригинальные и скомпилированные версии выполнялись в отдельных VM-контекстах. Полный исполняемый AST обоих модулей совпал после удаления комментариев и координат текста. Проверялись ключи публичного API, имена и арность функций; примитивные значения сравнивались через `Object.is`.

| Проверка                        | Результат                                                                                                                                                                                     |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Состояние                       | Четыре созданных объекта: начальные и изменённые значения совпали; новые экземпляры не разделяют состояние, игрока или управление                                                             |
| Изменяемость                    | Объекты расширяемы и не заморожены; исходные поля имеют прежние writable/enumerable/configurable-дескрипторы                                                                                  |
| Управление                      | Null-прототип сохранён; сброс выполняется на месте и не добавляет отсутствующие поля; проверены специальные имена `constructor` и `__proto__`; символы и неперечислимые поля не затрагиваются |
| Изолированные результаты миссий | Все пять статусов (`inactive`, `too-far`, `too-fast`, `pickup`, `delivery`) совпали, включая сообщения, порядок вызовов и возвращаемое `undefined`                                            |
| Настоящие маршруты              | 14 взаимодействий: результаты, состояние прогресса и упорядоченные побочные эффекты совпали; три доставки дали 5400 кредитов, восстановили батарею и замкнули цикл маршрутов                  |
| API контроллера                 | Заморозка объекта и передача исходного объекта точки в `markers.launch` сохранены                                                                                                             |

Сценарии включают неактивную игру, недостаточную близость, превышение скорости вперёд и назад, точные границы допустимых расстояния/скорости, приём груза, паузу с грузом, отказ доставки, успешную доставку и следующий приём после полного цикла. Снимки состояния записывались при каждом вызове порта: изменения прогресса происходят до запуска маркера, затем уведомление и обновление HUD в прежнем порядке.
