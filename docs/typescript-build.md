## Почему две проверки TypeScript

`tsconfig.contracts.json` сохраняет `strict`, `checkJs`, `noEmit` и список 11 файлов.
Дополнительный `include` охватывает будущие `.ts` и `.d.ts` под `src/`. Все они
проверяются в одной программе вместе с `types/game-contracts.d.ts`; существующие
глобальные JSDoc-типы доступны TypeScript. Объявление TBS остаётся в одном месте,
не нужно повторно объявлять `var TBS` в каждом файле.

`tsconfig.build.json` выдаёт только `.ts` → `.js`, не копирует JSDoc-модули и не
перезаписывает `src/`. `rootDir: src`, `outDir: dist`, `target: ES2022`,
`moduleDetection: legacy`, `module: Preserve`. TypeScript 7 не предоставляет
`module: none`; отсутствие модульного синтаксиса контролирует скрипт сборки.

Emit использует `noCheck`, потому что JSDoc-типы находятся в ещё не мигрированных
JS-файлах. **Перед каждым emit сборщик обязательно выполняет полный строгий
typecheck общей программы.** Не запускайте emit-конфигурацию напрямую вместо
`npm run build`. Watcher выполняет ту же строгую проверку на каждой пересборке.

Результат проверяется штатным парсером ESLint как classic script; запрещены также
динамический `import()` и CommonJS `require`/`exports`. При ошибке типизации,
компиляции, проверки формата или конфликте `.ts`/`.js` сборка не обновляет `dist/`.
Сохраняется последняя успешная версия; ошибка видна в терминале.

Компиляция сначала идёт в новый игнорируемый каталог
`artifacts/typescript-build-*`, затем проверенные результаты копируются в `dist/`.
Существующие диагностические каталоги не перезаписываются и не удаляются.
Сборщик обнаруживает лишние `.js` в `dist/`, но не удаляет их самостоятельно.

## Правила постепенного перехода

Следующий этап выполняется отдельно, по одному модулю:

1. Заменить исходник, например `src/domain/math.js`, на `src/domain/math.ts`.
   Не оставлять обе версии в `src/`: сборка считает это конфликтом.
2. Сохранить существующую регистрацию `globalThis.TBS.domain.math` и её поведение.
   Оборачивать локальные объявления в IIFE, чтобы не создавать новые глобальные
   переменные. Не добавлять runtime `import`/`export`.
3. Если файл входит в `files` контракта, заменить там путь `.js` на `.ts`.
   Перенести его JSDoc-typedef в соответствующее глобальное объявление типа,
   сохранив имена, используемые соседними JS-модулями; не дублировать типы.
4. Выполнить `npm run build`. Результат примера: `dist/domain/math.js`.
5. Заменить **на том же месте** в `index.html`
   `<script src="src/domain/math.js"></script>` на
   `<script src="dist/domain/math.js"></script>`.
   Оставить остальные подключения и `src/bootstrap/namespace.js` без изменений.
   Не добавлять `type="module"`, `async`, `defer` или загрузчик через `fetch`.
6. Обновить пути соответствующих тестовых fixtures на скомпилированный JS,
   проверить поведение и браузер. Это ещё не выполнено на подготовительном этапе.

Смешанная загрузка `src/**/*.js` и `dist/**/*.js` остаётся последовательной:
namespace создаётся раньше потребителей, зависимости — раньше модулей, bootstrap
и app — последними. Файлы доступны через относительные URL; браузеру не нужны
HTTP-сервер, npm, ES-модули или сетевой доступ.

## Git и форматирование

Хранить в репозитории `.ts`, объявления типов, конфигурации, инструмент сборки,
`index.html` и **все соответствующие `dist/**/*.js`**. После клонирования сразу
работает последняя проверенная сборка. Разработчику нужен `npm ci` только для
изменения исходников и проверок. При переносе на другую ОС проверка допускает
Git CRLF/LF, но не изменение содержимого сгенерированного кода.

Не редактировать `dist/` вручную. Он исключён из общего форматирования и ESLint,
но проверяется на classic scripts и точное совпадение со свежей компиляцией.
Текущий ESLint продолжает проверять существующие JS и границы слоёв; синтаксис
и типы `.ts` проверяет TypeScript. TypeScript ESLint-парсер не добавлялся.
`npm run check` также не меняет сгенерированные файлы: устаревшая или отсутствующая
сборка вызывает ошибку и требует `npm run build`.

`node_modules/`, `artifacts/`, логи и дампы остаются игнорируемыми. Lockfile и
зависимости не изменены. На этом этапе нет коммита, push или миграции игровых файлов.
