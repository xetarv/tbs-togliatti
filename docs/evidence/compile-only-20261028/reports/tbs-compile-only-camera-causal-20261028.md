## 1. Отключение механизма по коду осуществимо

Проверены точные восемь замен сохранённого `patch-spec.json`: применение их
к исходному Safe побитово воспроизводит vendor текущей B.
Исходный Safe SHA256:
`5fb78aeaa9ba4092eacdf2018e8e757aebc53eed0f3a98f7202cb7aa8c5684a0`;
B Safe:
`061f51c90a5e594fb344732929a6938ebb5475580f75cfb13347a24b95457fb3`.

Контрольные точки:

- `src/adapters/rendering/graphics.ts:569–573`: после обычного `setQuality`
  создаётся Map четырёх существующих материалов и cubemap-источников.
- Safe, последняя замена `include cohort in same owner before unchanged readiness loop`:
  исходные четыре прохода выполняются всегда; дополнительный обход вызывается
  только при `!signal?.aborted && renderer.__compileOnlyEnvMaps`.
- `src/app.ts:173`: штатный вызов `compileAsyncPasses(passes(), {signal})`.
  App удаляет эту Map в finally; graphics disposal также удаляет её.

Достаточная внешняя интервенция — удалить только собственное свойство
`__compileOnlyEnvMaps` непосредственно перед исходным вызовом подготовки,
в уже существующей диагностической обёртке метода, сохранив `this`, аргументы
и возвращаемый исходный Promise. Схема, **не применённая в браузере**:

```js
// Inside the existing diagnostic compileAsyncPasses wrapper:
delete this.__compileOnlyEnvMaps;
return Reflect.apply(originalPrepare, this, args);
```

Одного выключения capability-флага после создания Map недостаточно: условие
дополнительного обхода читает Map, а не `__compileOnlyEnvMapsSupported`.

После удаления Map дополнительная ветка пропускается. Исходные четыре вызова
compile получают прежние options без `compileOnlyEnvMaps`; scalar `tbsEnv`
остаётся undefined. Все добавленные условные выражения `getParameters`/`Ut`
исполняют исходный путь разрешения envMap. Render-путь не передаёт descriptor.
Дополнительный проход не создаёт свои семь программ до первого render;
они вновь могут создаваться штатным первым render.

Таким вмешательством сохраняются адаптированный renderer B, исходный цикл
readiness/reflection, shader checks, графические настройки, материалы и реальные
кубические targets, камера, строительство мира и порядок игровых конструкторов.
До вмешательства весь buildWorld/buildGame уже выполнен одинаковым кодом B.
Не требуются подмена vendor, синтетическая compile-сцена, изменение материалов,
скрытая отрисовка, принудительная линковка или другой порядок графических проходов.
Удаление входа подготовки и его последствия для program cache — исследуемая
интервенция. Это статическое обоснование изоляции на уровне приложения;
runtime-исполнение отключения в этом задании не проверялось.

## 2. Почему единственный причинный запуск сейчас не выполнен

Все сохранённые текущие camera A1/A2/A3/B содержат точную browser version
**156.0.4314.42**. Установленный executable прежнего runner:

```text
C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
```

имеет FileVersion/ProductVersion **156.0.4314.50**. В проверенной папке установки
есть каталоги `155.0.4283.62` и `156.0.4314.50`; каталога `.42` нет.
Не утверждается, что выполнен поиск старого executable по всему компьютеру.

Следовательно, при сравнении единственного B-disabled/.50 со старыми кадрами
меняются как минимум два фактора: наличие compile-only подготовки и browser build.
Ни влияние patch-обновления Edge, ни его отсутствие не доказаны. Совпадение
версии major=156 или одинаковый GPU/backend не устраняют этот confound.
Последний A/B производительности на `.50` camera-RGBA не сохранял и не служит
новым matched camera-контролем. Исторические A на Edge155 также не заменяют его.

Поэтому причинная изоляция **всего предложенного однократного опыта** не подтверждена,
хотя технический выключатель подготовки существует. Не запускались A4/A5,
новая обычная B, B-disabled, старый Edge155 или обход с подменой browser version.

## 4. Единственный минимальный следующий шаг

Отдельно согласовать **одну сопоставимую пару на неизменной B**:
обычная B и B с удалённым входом compile-only на одной точной установленной версии
Edge `.50`, с прежним фиксированным camera-сценарием и контролем условий/CPU.
Это два B-запуска, не A4/A5, и выходит за разрешённый здесь один запуск —
поэтому сейчас не выполнялось. Оно устраняет установленное различие browser build
между экспериментом и его прямым контролем; не обещает устранить все источники
вариативности или автоматически закрыть строгий visual gate.
