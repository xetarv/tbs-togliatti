# Перенос на другой ПК

Кандидат отклонён: повторный запуск медленнее, первый framebuffer отличается, возможна задержка после раннего Start. См. [отчёт](report.md) и [полную сводку A/B](summary.json). Production-интеграция не одобрена; пакет 2 и FPS-работа не начаты.

## Полный переносимый эксперимент

Скачайте **все пять отдельных ZIP**:

- [evidence-part-01.zip](evidence-part-01.zip)
- [evidence-part-02.zip](evidence-part-02.zip)
- [evidence-part-03.zip](evidence-part-03.zip)
- [evidence-part-04.zip](evidence-part-04.zip)
- [evidence-part-05.zip](evidence-part-05.zip)

Это независимые обычные ZIP, а не тома одного ZIP. Распакуйте каждый в корень клона репозитория с сохранением путей. Восстановится `artifacts/r149-async-principle-20261019/`. Не распаковывайте поверх существующего одноимённого каталога с чужой работой.

Включены код прототипа, оригинальные официальные исходники для сравнения, точный engine-patch, все сырые A/B JSON и trace.gz, изображения и RGBA, visual A1/B/A2, проверки механизма, hashes и условия. [Манифест](archive-manifest.json) перечисляет файлы и их архивы. Браузерные профили исключены: их нет в пакете.

Четыре незакоммиченных изменения shaderChecks сохранены как **копии** в `artifacts/r149-async-principle-20261019/saved-local-changes/` с исходными относительными путями. Для точного воспроизведения исходного состояния сначала сравните их с клоном, затем вручную восстановите только эти четыре файла. Они не применяются автоматически и не включены в production этого коммита. Оригинальная `assets/three.min.js` должна соответствовать `preserved-before.json`.

После проверки исходного состояния `node artifacts/r149-async-principle-20261019/prepare.cjs` пересоздаёт **только экспериментальные копии** и HTML с правильными абсолютными file:// путями нового ПК. Уже готовые `run-ab.cjs`, `visual.cjs`, `check-mechanism.cjs` находятся в архиве; генераторы runner/visual ссылаются на исторические локальные материалы и для переноса не требуются. Существующие измерения не перезаписывать; новые запуски — только по отдельному поручению и с новыми именами результатов.

Исходная игровая база: `89613bbf312bbb053de05471b98ee1f8747f5739`; HEAD при работе `efffd0b268e63e98bfe0571f30a00ec420c0c986` (поверх базы только отчёт меню). Текущая публикация разрешена пользователем после завершения эксперимента специально для продолжения на другом ПК. Игровые файлы и историческая диагностика не изменялись.
