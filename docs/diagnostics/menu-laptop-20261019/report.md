# TBS: появление и отзывчивость меню — оконный Edge, 19.10.2026

## Вывод

Меню уже присутствует в композиторном изображении через **0,516 с** в новом профиле и **0,214 с** в повторном. Отправленное сразу после его появления настоящее событие колеса обрабатывается главным потоком лишь на **15,618 / 3,797 с**. Успешное нажатие Start подтверждено на **16,244 / 4,126 с**, положительная скорость после W — на **16,299 / 4,183 с**.

Главный измеренный источник ожидания в новом профиле — синхронная готовность/проверка шейдерных программ внутри первого полного 3D-рендера: **12,237 с** внутри `getProgramInfoLog`, при полной длительности этого рендера **12,484 с**. Это место синхронизации с подготовкой программ, а не доказанная стоимость формирования текста лога. Меню появляется раньше этой задержки и затем остаётся без подтверждённой реакции на отправленный ввод.

Один обоснованный следующий объект исправления — блокирующая подготовка программ первого полного кадра. Это измерение не разрешает новую реализацию пакетной компиляции и не доказывает, что простое отключение проверок устранит ожидание.

## Условия и метод

- HEAD `89613bbf312bbb053de05471b98ee1f8747f5739`, обычный `file://index.html` без query-параметров; `shaderChecks=true`, эксперимент пакетной подготовки не подключался.

- Внутренняя область 1528×694 CSS, внешнее окно 1536×824 CSS, экран 1536×864 CSS, DPR 1,25, WebGL drawing buffer 1910×867. Скринкаст уменьшен до 1600×726. Полная командная строка браузера недоступна через CDP; заданные аргументы, фактические размеры и renderer записаны в raw JSON.
- Три пары: отдельный новый профиль для каждой пары, затем закрытие и повторный запуск браузера с тем же профилем. Порядок fresh-1 / warm-1 / fresh-2 / warm-2 / fresh-3 / warm-3. Новый профиль **не означает холодный системный или драйверный GPU-кэш**; эти кэши не очищались и их состояние не установлено.

- Ноль времени — `performance.timeOrigin` навигации. Трассы привязаны через `tbs.diag.anchor`. Внешний запрос навигации предшествует ему на несколько миллисекунд; хранится отдельно.
- DOM обнаружен MutationObserver. Paint/FCP взяты из PerformancePaintTiming. Видимость меню подтверждена пикселями композиторных PNG, не появлением DOM. Скринкаст не измеряет физическую развёртку LCD; время первого обнаруженного изображения — верхняя граница момента появления в доступной записи. Возможна погрешность сопоставления часов в несколько миллисекунд.
- Во всех шести прогонах ровно одно настоящее событие wheel и один настоящий click с `isTrusted=true`, затем настоящий KeyW через CDP, без DOM `.click()`. После согласованной паузы пользователя внешних wheel-событий в финальной серии нет.
- При этой высоте окна кнопка `#startBtn` («Начать смену →», в задании «Войти в игру») первоначально ниже видимой части карточки или видна частично. Скрипт отправляет wheel сразу после первого изображения меню, ждёт кадр с полностью распознанной кнопкой, затем нажимает её. Возможность прокрутки проверяется настоящим браузерным вводом, без изменения HTML.
- Ответ Start подтверждён после штатного обработчика: `mode=playing` и overlay скрыт; отдельно записан первый кадр без overlay. Движение — первый `game.step` с положительной скоростью после настоящего W, затем конечные координаты. Во всех прогонах конечный x около 54,25–54,28 против исходных 68; конечная скорость иногда уже нулевая, её не используем как критерий первого движения.

В trace анализируется только внешний `ThreadControllerImpl::RunTask` главного renderer thread, без сложения вложенных RunTask/EvaluateScript/native вызовов. Первая длинная bootstrap-задача начинается примерно на 0,15–0,19 с, до первого изображения меню, и продолжается после его появления: 2,601–2,719 с в новых профилях и 2,308–2,472 с в повторных. Она включает построение мира и buildGame.

Затем отдельная задача первого полного кадра блокирует поток на **12,338–12,552 с** в новых профилях и **0,888–0,932 с** в повторных. Например, fresh-1: bootstrap 0,166–2,884 с; полный кадр 2,969–15,307 с. Таким образом, меню уже видно во время bootstrap; крупнейшая последующая заморозка совпадает с первым тяжёлым рендером, а не с созданием самого DOM меню.

В каждом первом полном кадре зарегистрировано 69 вызовов getProgramInfoLog (это число вызовов, **не утверждение о 69 уникальных программах**). Наиболее долгий одиночный вызов 0,378–0,400 с в новых профилях / 0,081–0,093 с в повторных. Суммарное время этих самостоятельных native-вызовов составляет примерно 98% длительности первого render в новом профиле. Это подтверждает синхронное ожидание подготовки программ на текущем пути с включёнными проверками. Отделить драйверную компиляцию от иных внутренних причин ожидания только этими таймерами нельзя.

## Достоверность и ограничения

- Это первое **подтверждённое** обслуживание заданного сценария scroll → Start → W. Не установлена математически самая ранняя возможная реакция на любое действие в меню: между задачами могли быть короткие окна, а повторные вводы для их поиска не посылались. Не следует называть поздний Start временем регистрации его обработчика или считать DOM доказательством отзывчивости.
- PNG раскрытой кнопки — верхняя граница видимой реакции прокрутки. Самый первый изменившийся пиксель анимации прокрутки отдельно не локализован; scroll event и изображение кнопки приведены раздельно. Paint Timing и композиторные timestamps могут отличаться на несколько миллисекунд.
- GPU fence относится к командам первого render, не доказывает готовность всех будущих day/night-вариантов или физическую презентацию экрана. Времена после Start включают задержку доставки CDP и самого диагностического наблюдения; абсолютный минимум времени идеального пользователя не измерялся.
- Во всех шести запусках page/console errors = 0, финальный WebGL getError = 0. Есть одинаковые два предупреждения PMREM о sigmaRadians/числе samples; новых критических ошибок не обнаружено. Единственная финальная проверка getError не доказывает отсутствие каждого возможного промежуточного GL error.
- Пилоты с эмулированным viewport, неудачным попаданием click и посторонними wheel-событиями исключены. Инфраструктурные ошибки получения browser command line/target случились до измерений. Эти файлы сохранены для происхождения решения. Для выводов используются **только шесть final-*.json и их traces**. `desktop-observation.png` снят после закрытия пилотного браузера и не является доказательством состояния Edge во время серии.
