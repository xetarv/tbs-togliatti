# Отсечение статических городских групп — этап 2

## Основание и выбор

Использованы сохранённые performance-audit.md и vegetation-culling.md. Полный аудит не повторялся. На текущей версии выполнены только три коротких CPU sampling-профиля (120 кадров каждый), census реальных проходов и два режима A/B. Разрешённый Edge использовал отдельный временный профиль; корпоративные политики не менялись. Все результаты относятся к ANGLE NVIDIA GeForce RTX 3050 Laptop / D3D11, 1024×768, DPR 1, High.

CPU-профиль старта: renderBufferDirect около 1440 мс inclusive в окне 3784 мс; корневой updateMatrixWorld около 554 мс inclusive. Эти времена перекрываются с дочерними вызовами и не складываются. Wall time рендера не равен чистому CPU-времени. GPU-время A/B получено отдельными асинхронными EXT_disjoint_timer_query_webgl2, 30 проб на окно; профилирование не включалось в FPS-окна.

Адресная перепись уточнила цель: 368 уже существующих статических InstancedMesh с shared unitBox, прямых детей scene, проходят в основной рендер во всех трёх ракурсах. Ещё 100 вызовов приходятся на их тени. Нельзя смешивать их с 231 вызовом вложенных автомобильных групп на той же геометрии. Ночная сцена и берег содержат мало обычных видимых meshes, но продолжают оплачивать эти 368 групп. Поэтому выбран один ограниченный способ уменьшить отправку геометрии: отсечение существующих статических групп, без нового batching или разбиения. Общий обход матриц и многочисленные обычные детали остаются следующими кандидатами, не оптимизированными в этом проходе. Это не утверждение об абсолютном максимуме всех возможных оптимизаций.

## Изменение и безопасность

- Единственный изменённый игровой файл: src/adapters/world/population.js, 7 добавленных строк и замена scene.add. После заполнения instance matrices регистрируются только уже существующие статические batches.
- Используется прежний проверенный r149 bounds-адаптер createVegetationCulling, с отдельным экземпляром переключателя и нулевым shader displacement. Файл vegetation-culling.js и всё построение растительности не менялись. Название фабрики осталось прежним, чтобы не проводить попутный рефакторинг.
- Разбиение 84×80, критерий минимум 3 объекта, материалы, порядок экземпляров, transforms, castShadow и receiveShadow сохранены. Ни новых batches, ни новых GPU-буферов нет. У статических unitBox отсутствует shader-анимация вершин; ветер относится к другой геометрии растительности, вода — к отдельной поверхности.
- В r149 геометрическая сфера не учитывает instance transforms. Поэтому AABB объединяет преобразованный Box3 всех экземпляров, включая поворот/масштаб. Проверяется отдельный world AABB с запасом 0,01. Родительские матрицы учитываются; изменения буферов приводят к консервативному пропуску до перерегистрации. Общая геометрия и библиотека не подменяются.
- visible не меняется: теневые камеры используют собственные frusta. Даже вне основной камеры группа может оставаться в теневом проходе. Копии без регистрации консервативно пропускаются. Отражения используют прежнюю proxy scene и прежнюю частоту обновлений.
- Технический переключатель index.html?staticBatchCulling=0 отключает только этот этап и сохраняет ту же структуру batches. vegetationCulling=0 управляет растительностью независимо. A/B использовал полный проверенный снимок рабочих файлов, а не этот переключатель.

## Методика A/B

128 исходных файлов текущей рабочей версии скопированы в artifacts/render-batches/baseline до изменений, с SHA-256 manifest. Это уже версия с оптимизированной растительностью; aa61f93 не является базой этапа 2. Файлы снимка проверяются перед каждым запуском. В конце также проверено, что из прежних файлов изменён только population.js. Незакоммиченные предыдущие изменения и сторонние неотслеживаемые файлы сохранены.

Сцены и seed совпадают с предыдущим коротким браузерным инструментом: start-day camera [77,8,40] target [55,3,28]; waterfront-night [94,7,30] → [115,2,0]; bank-day [25,12,-40] → [55,1,-65]. Свет установлен перед захватом, ветер фиксирован на 12. Текстуры ожидаются до измерения. Runtime, физика и анимация мира заморожены только диагностическим init-script; игра не менялась.

Каждый режим: A → B → B → A, свежая страница на повтор; 10 прогревочных рендеров и 120 rAF кадров (119 интервалов), по два окна каждой версии на сцену. Итоговый FPS = 1000 / объединённое среднее время кадра. Основной режим render(0) измеряет стабильный рендер без повторных отражений. Дополнительный render(1/60) сохраняет регулярные обновления отражений; камера и мир остаются фиксированы. dt задан фиксированно для одинакового расписания отражений, а не взят из замеров.

Это FPS контролируемого headless render loop, а не FPS физического монитора или полного игрового шага. Тест не измеряет управление и физику в окнах FPS. Их сохранность проверяется штатным browser smoke test отдельно. Несколько коротких окон не заменяют длительное тепловое тестирование ноутбука.

## Визуальное качество, память и проверки

Framebuffer SHA-256 совпал для всех трёх сцен во всех повторах обоих режимов; PNG сохранены в artifacts/render-batches. Сравнение включает итоговый кадр с тенями, материалами, водой, освещением и постобработкой; это сильнее ручного сравнения этих конкретных ракурсов, но не покрывает все возможные положения камеры. Изменение убрало основной static census 368 → 33/30/14, теневой 100 → 22, не убрав видимые тени.

В каждом образце сохранены 308630 экземпляров, 1039 InstancedMesh, 19772800 байт матриц и 3369504 байта instanceColor. После принудительного GC retained JS heap остаётся около 105 MB, без значимого роста; отдельные значения и p95 каждого окна находятся в render-batches-data.json. renderer.info.memory показывает те же геометрии; число загруженных текстур иногда на одну меньше, потому что отсечённый материал не загружается на GPU, его ассет и объект остаются в мире. Это счётчики ресурсов, не полное измерение VRAM. Длительный тест памяти не повторялся.

Добавлены три теста реальной populateWorld: сохранение transforms/flags/плотности с погрешностью Float32; выступающая в frustum масштабированная/повёрнутая геометрия; отдельная камера тени и движение родителя; независимость переключателей; сохранение критериев batching для вложенных/крупных объектов. Существующие 38 тестов сохранены. npm run check: ESLint, Prettier и 41 тест успешно.

Штатный npm run test:browser также успешно выполнен в разрешённом Edge: offline launch, driving, pause, camera, lighting, audio, resize, все graphics presets и mobile touch controls. Это функциональная проверка настоящего работающего runtime, отдельно от контролируемых FPS-окон. Снимки старта и берега дополнительно просмотрены; они показывают полноценную сцену, а не пустой framebuffer.

Файлы этапа: population.js; tests/static-batch-culling.test.cjs; tools/check-render-batches.cjs; docs/render-batches.md; docs/render-batches-data.json. Скрипты index.html и их порядок не менялись. Тест запускается Node с TBS_BROWSER указывающим разрешённый Edge и TBS_TEST_ANGLE=d3d11; --probe только профилирует baseline, --reflections выбирает дополнительный режим. Для повторения A/B нужен сохранённый baseline и baseline-manifest.json; snapshot не следует перезаписывать текущими файлами.

## Ограничения и следующий проход

Устойчивая польза подтверждена на этом RTX 3050 Laptop в заданных сценах; результаты других GPU не объединялись. Долгие поездки, все ракурсы города, нагрев/питание ноутбука и мониторная частота отдельно не измерены. При добавлении анимации вершин статическим batches потребуется запас bounds; при изменении instance buffers — перерегистрация. Нынешние группы неподвижны. Изменение можно оставить; следующий узкий проход — текущая стоимость updateMatrixWorld или обычных деталей старта, с адресной проверкой перед изменениями. Коммитов и отправки на GitHub нет.
