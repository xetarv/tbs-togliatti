# Этап №28: симуляция пешеходов на TypeScript

13 октября 2026 года. Основа: `8fd29b4acbf6954e8ca3c13d68587dc822cab6eb`. Переведён только `src/adapters/simulation/pedestrians.js` → `pedestrians.ts`. Теперь 33 производственных TS-модуля; `build-smoke.ts` считается отдельно.

## Изменения и контракты

- Используется существующая сборка. Результат — `dist/adapters/simulation/pedestrians.js`, classic script без runtime import/export. Регистрация `window.TBS.createPedestrians` и незамороженный API `{ updatePedestrians }` сохранены.
- В HTML заменён только соответствующий путь, порядок и остальная разметка совпали. Старый JS-исходник удалён после сохранения копии.
- Вход `PedestriansOptions` переиспользуется: реальные `mat`, `box`, Three.js, сцена, камера, материалы, текстура, параметры дорог, `isParkBlock`, `special.has`, `lowPower` и `PresentationState`. Bootstrap передаёт прежний объект, DI не менялся.
- `types/pedestrians-contracts.d.ts` описывает `PedestrianLimb`, `PedestrianData`, `PedestrianRoot`, `PedestrianState`: группы рук/ног и корпуса, ссылки `userData`, изменяемый маршрут `PointXZ[]`, target, speed, wait, arrivals, phase, seed.
- В существующие Three.js-контракты добавлены реальные операции r149: `Group.traverse`, `Mesh.castShadow`, `Vector3.distanceToSquared`, конструкторы Sphere/Plane/CircleGeometry, параметры `map` и `toneMapped` материала. Обход различает Mesh через существующий runtime-флаг `isMesh`, без новых проверок в игре. Первый typecheck выявил неподходящий автомобильный тип узлов обхода; он заменён общим существующим Mesh-контрактом с реальным `castShadow`.
- Единственное утверждение типа — `return root as PedestrianRoot`, после фактического присваивания `{ body, limbs }` в `userData`. Оно не добавляет исполняемый код. `any`, подавлений ошибок и ослабления strict нет.
- В TS-конфигурацию добавлены декларации и исходник; README и текущий статус сборки обновлены. Тестовые пути не потребовали изменений. `simulation/traffic.js`, сборщик, зависимости и остальные игровые алгоритмы не затронуты.

## Детерминированное сравнение

Сравнивались сохранённый исходный JS и скомпилированный JS. Их полный исполняемый AST совпал после исключения комментариев и координат текста. Это также подтверждает отсутствие дополнительных runtime-операций, аллокаций и изменений кадрового цикла вследствие миграции; отдельное профилирование FPS или памяти не проводилось.

Обе версии загружались в независимые VM с настоящим поставляемым Three.js r149. Random был детерминирован для совпадения UUID ресурсов. Использовались настоящие состояния игры и презентации, параметры конфигурации, координаты special-блоков из действующей population.js, и точные реализации используемых mat/box из world/resources.js. Только диагностические копии получили доступ к внутреннему массиву пешеходов; игровой API не расширялся.

Во всех сценариях точно совпали начальные координаты, направления, скорости, целевые участки, маршруты и их порядок; дерево объектов, трансформации, все данные геометрии/индексов/атрибутов, JSON материалов и совместное использование ресурсов. Проверены ссылки body/limbs, варианты одежды, значки, масштабирование, цвета, нормали, тень и castShadow при обоих lowPower.

На каждом кадре сравнивались позиции, повороты, target, speed, wait, arrivals, phase, seed, видимость, углы конечностей и вертикальное движение корпуса. Примитивы сравнивались через `Object.is`. В каждом сценарии проверены шесть кадров intro/paused без изменения движения, ожидания и анимации; visibility продолжала обновляться. Пешеходы за пределами камеры продолжают симуляцию, как прежде.

Для покрытия периодического ожидания диагностическая подготовка восьмого кадра разместила первого пешехода в 0,002 от цели и задала два предыдущих прибытия одинаково в обеих версиях. Следующее прибытие действительно стало третьим и установило wait=0,8; проверены отсчёт ожидания, переход к следующей точке и последующий поворот. На кадрах 18/19 проверены точная невидимая граница 110 и видимое расстояние 109,999. Visibility сравнивалась относительно позиции до движения текущего кадра, как в исходном алгоритме.

## Проверки и ограничения

- `npm run build`, `npm run check`, `npm run build:check` прошли: strict typecheck, ESLint, Prettier, 49/49 тестов и актуальность всех 34 classic scripts (33 производственных и один технический).
- Edge file:// прошёл: штатные сценарии запуска, езды, паузы, камеры, освещения, звука, изменения размера, графических режимов и мобильного сенсорного управления. В диагностической копии существующего теста добавлены наблюдения пешеходов; производственные код и тестовый инструмент не менялись. Desktop: 60 пешеходов, 116 обновлений, 73 обновления с движением, 14 на паузе, 113 изменений камеры и 6960 проверок видимости. Mobile: 60 пешеходов, lowPower=true, 52 обновления с движением, 50 изменений камеры и 3120 проверок видимости. Нарушений нет. Число браузерных кадров зависит от времени выполнения теста и не является измерением FPS.
- Побитового сравнения снимков не выполняли. Совпадение геометрии, материалов и состояний подтверждено; побитовая идентичность рендера и изменение FPS не заявляются. Структурные Three.js-контракты описывают реально потребляемые операции, а не всю библиотеку; тела немигрированных world-хелперов остаются JS.
