## Файлы и контракты

- Единственный редактируемый источник адаптера — `traffic.ts`. Сборка создаёт `dist/adapters/simulation/traffic.js` как classic script. Регистрация в `window.TBS` и замороженный API `{ update }` сохранены.
- В `index.html` заменён один путь относительно состояния после этапа №28; положение скрипта и остальная разметка совпали. Старый JS удалён после сохранения копии.
- Входы `TrafficViewOptions`, `TrafficVehicle`, `TrafficSimulation`, `SignalPhase`, `TrafficCar`, `CarModels`, `GraphicsPort`, `GameFramePorts` переиспользуются без изменения DI и фактических объектов.
- `types/traffic-view-contracts.d.ts` адресно дополняет существующие r149-контракты: Matrix4.clone/multiplyMatrices/toArray, Matrix3.getNormalMatrix/toArray, Vector3.setFromMatrixPosition/applyMatrix4, geometry.clone/setAttribute, InstancedBufferAttribute с Float32Array/setUsage/needsUpdate, матрицы группы и камеры, Material UUID/needsUpdate/onBeforeCompile/customProgramCacheKey и render-обработчики Mesh/Scene.
- Сигнатуры Mesh render callbacks сохраняют шесть аргументов; Scene получает renderer, scene, camera и renderTarget. Это проверено по поставляемому WebGLRenderer r149. Тип камеры render-прохода допускает реальные Perspective/Orthographic камеры; положение игровой камеры проверяется прежним контрактом.
- `ThreeCompiledShader` описывает vertexShader, fragmentShader и реальный словарь uniforms с неоднородными непрочитанными значениями `unknown`. У функций compile и Scene.onBeforeRender явно указан `this`; обычные функции не заменены стрелками.
- Внутренние типы описывают головы/лампы/необязательный active, детали корпуса с единственным материалом, записи матриц, порядок и глубину, Map по ключу ячейки и Map автомобилей по ID.
- Утверждение типа head.children описывает только Mesh-детали, фактически созданные этим кодом; parent читается до removeFromParent. Non-null assertions у Map.get отражают существующее создание записей до чтения. Новых fallback, проверок и runtime-ветвлений нет; исходное поведение при нарушении этих инвариантов не менялось. `any`, подавлений ошибок и ослабления strict нет.
- В TS-конфигурацию добавлены декларации/исходник. В `tests/signal-housing.test.cjs` изменён только путь загрузки, ожидания сохранены. Обновлены README и текущий статус сборки. Зависимости, сборщик, другой игровой код и GLSL не менялись.

## AST и детерминированное поведение

Полный исполняемый AST скомпилированного файла совпал с сохранённым JS после исключения комментариев и координат текста, включая compile, onBeforeRender, onAfterRender, ключ `:signal-exact-r149` и все строки GLSL. TypeScript не добавил исполняемых операций или аллокаций. FPS и общая производительность не профилировались.

Сравнение выполнялось в независимых VM с настоящими Three.js r149, domain traffic, конфигурацией и неизменённой vegetation-culling. Random фиксировался для UUID. Для createTrafficCar/animateVehicle использован детерминированный наблюдатель с настоящими Group/Mesh: проверялись аргументы фабрики, идентичность объектов, координаты, повороты, видимость и вызовы анимации. Реальные модели проверяются отдельно в браузере; эта VM-проверка не заменяет тест их внутренней геометрии.

| Режим                          | Головы / лампы / автомобили | Группы / экземпляры корпусов | Обновления / проходы камеры | Вызовы анимации | Регистрации culling |
| ------------------------------ | --------------------------- | ---------------------------- | --------------------------- | --------------- | ------------------- |
| По умолчанию, batching включён | 252 / 756 / 36              | 40 / 1260                    | 12 / 24                     | 110             | 297                 |
| `?signalHousingBatching=0`     | 252 / 756 / 36              | 0 / 0                        | 12 / 24                     | 110             | 0                   |

В каждом режиме исходная и новая версии точно совпали по структуре светофоров, материалам и ссылочному совместному использованию ресурсов, расположению, фазам red/amber/green, ID и порядку деталей. Сравнивались байты instanceMatrix/model-view/normal Float32-буферов, их версии, порядок записей, local/instance/view матрицы и глубины, динамическое использование атрибутов, результаты frustum culling и порядок register-вызовов. Проверены две позиции камеры и дополнительные преобразования Scene с неравномерным масштабированием.

Обработчик исходной Scene вызывается первым с прежним `this` и аргументами. Включённый batching проверялся с пользовательскими исходными compile/key обработчиками: originalCompile получает тот же материал как `this` и тот же renderer; строки шейдера совпадают, вариант ключа сохранён. После каждого batch-render восстанавливаются именно исходные ссылки onBeforeCompile/customProgramCacheKey. В выключенном режиме обработчики остаются исходными и специализированные batch-атрибуты не создаются.

Переключения фаз использовали действующую domain.signalPhase с одинаковым контролируемым временем. Автомобили обновлялись действующей domain-симуляцией; проверены несколько значений графической дистанции, включая ноль. Геометрия/тени/порядок относительно обычных Mesh дополнительно прошли все четыре существующих профильных теста.

Первый запуск диагностического сравнения встретил разные прототипы массивов двух VM при одинаковых элементах: диагностическое сравнение исправлено на рекурсивное сравнение значений через Object.is. Это не изменение игровых проверок или их ожидаемых результатов; первоначальный лог сохранён.

## Проверки браузера и ограничения

- `npm run build`, `npm run check`, `npm run build:check` прошли: strict TypeScript, ESLint, Prettier, 49/49 тестов и актуальность 35 classic scripts (34 производственных и один технический).
- Edge file:// прошёл в обоих режимах существующим smoke-тестом, расширенным наблюдениями только в диагностической копии. Проверены холодный запуск, езда, движение 36 настоящих машин, все три фазы и лампы, пауза, качество, камера, мобильное управление, callbacks после render и диагностика реально скомпилированных WebGL-программ. Нарушений, ошибок браузера/WebGL или компиляции шейдеров не обнаружено; после контролируемых фаз отдельно проверялись console/page errors.
- Первый Edge-наблюдатель сравнивал Color.getHex с исходными RGB-числами и сообщил ложные расхождения. В игре ColorManagement.legacyMode=false; преобразование цвета может дать разницу в единицу канала. Диагностическая палитра теперь создаётся тем же THREE.Color и сравнивается в той же системе цвета. Производственные цвета, параметры ColorManagement и код игры не менялись. Логи и краткий отчёт исследования сохранены.
- Снимки сохраняются для просмотра, но детерминированного пиксельного A/B не выполнялось: анимированные контрольные кадры нестабильны. Побитовая идентичность изображения не заявляется.
