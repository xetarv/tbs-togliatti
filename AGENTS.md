# Правила работы с TBS Togliatti 2040

Перед изменениями проверь рабочую папку, ветку, HEAD и Git status.
Текущее состояние и ссылки на проверки — в [docs/project-state.md](docs/project-state.md).
Сохраняй уже существующие локальные изменения; не предполагай, что всё опубликовано.

## Архитектура и совместимость

- `src/domain` — чистая игровая логика без браузера и Three.js.
- `src/application` — игровые сценарии через переданные зависимости и интерфейсы.
- `src/adapters` — браузер, графика, управление, звук и окружение.
- `src/bootstrap` — связывание компонентов. Используй существующий реестр `window.TBS`;
  чистые слои регистрируются в `globalThis.TBS.domain` и `.application`.
- Сохраняй Three.js r149, запуск `index.html` через `file://` и порядок classic scripts.
  Не вводи runtime ES-модули, bundler или обязательный HTTP-сервер.
- Не редактируй `dist` вручную: изменяй `.ts`, получай JS существующей сборкой.
  Исходники и соответствующий dist хранятся вместе для запуска после клонирования.

## TypeScript и ESLint

- Производственные сборка и strict typecheck используют TS7 через `@typescript/native`.
  TS6 служит исключительно совместимым API для парсера ESLint.
- Не меняй разрешение компилятора без проверки фактической версии и назначения.
- Сохраняй strict, проверки слоёв и охват исходников/деклараций.
  Не добавляй `any`, `@ts-ignore`, массовые исключения или ослабление правил
  без обоснованной необходимости.
- Не выдавай декларации границ оставшихся JS-фабрик за проверку их внутренней реализации.

## Рабочий процесс и отчёт

- Выполняй минимальные изменения только в файлах конкретной задачи.
  Не повторяй общий аудит, рефакторинг или оптимизацию без причины.
- Для изменений исходников: `npm run build && npm run check`.
  Для остальных изменений выбирай достаточные проверки; не дублируй сборки и тесты,
  уже выполненные общей командой. В PowerShell при блокировке npm.ps1 используй npm.cmd.
- Проверяй форматирование изменённых файлов и `git diff --check`.
  Сохраняй прежние диагностические материалы; не перезаписывай исторические результаты.
- Не создавай коммит и не выполняй push без отдельного разрешения.
  Не используй `reset --hard`, `git clean`, rebase или force push для принудительной очистки.
- Сообщай фактические изменения, проверки и ограничения. AST-эквивалентность
  не доказывает пиксельную идентичность; прирост FPS требует измерений.
- После согласованного задания остановись. Следующие этапы самостоятельно не начинай.
