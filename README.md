# ТБС: Тольятти 2040

Откройте `index.html` двойным щелчком в современном браузере с поддержкой WebGL. Интернет для самой игры не нужен: Three.js сохранён локально в `assets/three.min.js`.

## Управление

- `W` или `↑` — ехать вперёд.
- `S` или `↓` — тормозить, затем ехать назад.
- `A`/`D` или `←`/`→` — поворачивать влево и вправо.
- `E` — принять или доставить груз у оранжевого маяка. Перед запуском дрона снизьте скорость.
- Пробел — ручной тормоз.
- `C` — переключить автоматическую камеру и управление мышью. В режиме мыши зажмите левую кнопку для вращения; колесо меняет масштаб.
- `P` — пауза.
- `M` или кнопка `♪` — включить/выключить звук.
- `N` или кнопка времени суток — день, вечер, ночь, автоматический цикл (5 минут).
- На телефоне используйте кнопки на экране.

Клавиши WASD определяются по расположению на клавиатуре, поэтому работают и при русской раскладке.

Звук включает двигатель, воду у набережной, городской фон и ближайшие автомобили. Громкость окружения зависит от расстояния; на паузе звук затихает.

Качество графики выбирается в верхней панели: «Низкое», «Среднее» или «Высокое». Выбор сохраняется в браузере. Для слабого компьютера начните с низкого режима.

В 3D-городе есть здания и флаги со знаком «ТБ», фотографии беспилотника и площадки компании на фасадах, три повторяемых задания, транспорт и мини-карта. Карта Тольятти стилизована и не предназначена для навигации.

Знак, логотип и фотографии взяты с [официального сайта «Транспорт будущего»](https://tb-drone.ru/) и [страницы «Транспорт Будущего Самара»](https://tb-drone.ru/transport-budushhego-samara/). Игра является неофициальным фанатским проектом.

3D-движок: [Three.js r149](https://github.com/mrdoob/three.js/tree/r149), лицензия MIT — `assets/THREE-LICENSE.txt`.

## Структура проекта

Игра работает без сборки, сервера и интернет-соединения. Исходный код использует обычные скрипты и единое пространство имён `window.TBS`, чтобы сохранялся запуск через `file://`.

```text
index.html                 Разметка и порядок подключения скриптов
styles/game.css            Оформление и адаптация к размеру экрана
src/app.js                 Запуск приложения и обработка ошибок запуска
src/bootstrap/             Сборка города, модулей и передача зависимостей
src/domain/                Правила движения, трафика, столкновений и заданий
src/application/           Игровой кадр, смена/пауза и взаимодействие с грузом
src/adapters/browser/      Планировщик кадров и состояние визуальных эффектов
src/adapters/world/        Материалы, дороги, здания, парки и анимация города
src/adapters/vehicles/     Сборка машин и дронов из отдельных компонентов
src/adapters/simulation/   Отображение трафика и анимация пешеходов
src/adapters/missions/     Маяки и эффекты запуска дрона
src/adapters/input/        Клавиатура, сенсорные кнопки и камера
src/adapters/rendering/    Сцена, освещение, качество и отражения
src/adapters/audio/        Двигатель, столкновения и звуки окружения
src/adapters/ui/           Приборы, мини-карта, пауза и уведомления
assets/                    Изображения, Three.js и сгенерированные данные
tests/                     Проверки игровой логики и управления
tools/                     Генератор модели машины и проверка в браузере
```

Правила в `src/domain/` не зависят от браузера, звука или Three.js. Настройки в `src/domain/config.js` защищены от изменения; состояние игры находится в `src/domain/state.js`. Физика возвращает события столкновения и зарядки. Трафик хранит координаты и скорости, а его 3D-представление создаёт адаптер.

Сценарии в `src/application/` получают небольшие интерфейсы звука, графики и уведомлений через аргументы. Сборка в `src/bootstrap/` подключает конкретные браузерные реализации. Настройки визуальных эффектов отделены от игрового прогресса. Подробные правила расширения проекта описаны в [документации архитектуры](docs/refactoring.md).

## Разработка и проверки

Для работы самой игры Node.js не требуется. Для инструментов разработки нужен Node.js 24 или новее:

```sh
npm ci
npm run check
npm run test:browser
```

`npm run check` запускает ESLint, проверку форматирования Prettier и тесты Node.js. `npm run format` применяет единый стиль; `npm run lint -- --fix` исправляет нарушения, поддерживающие автоматическое исправление. ESLint также проверяет границы игровых слоёв и сложность игровой логики. Сторонняя библиотека и сгенерированные ресурсы исключены из форматирования и анализа исходного кода. Проверки настроены для GitHub Actions после загрузки изменений в репозиторий.

Браузерная проверка открывает `index.html` через `file://` в Chrome или Edge и проверяет загрузку ресурсов, движение, паузу, камеру, освещение, звук, изменение размера окна и все режимы графики. Также проверяет автоматический запуск через `?play` и сенсорный газ на экране телефона. На другой системе задайте переменную `TBS_BROWSER` с путём к установленному браузеру Chromium. Снимки проверки сохраняются в `artifacts/` и не входят в исходники.

Генератор модели машины не запускается при импорте и может сохранить результат в отдельный файл для сравнения:

```sh
python tools/build_hero_car.py --output artifacts/generated-fastback.js
```

При добавлении модуля зарегистрируйте фабрику в соответствующем пространстве имён (`TBS.domain`, `TBS.application` или `TBS` для адаптеров), подключите файл перед `src/app.js` в `index.html` и передайте зависимости в `src/bootstrap/`. Изменение игровых правил следует сопровождать тестом поведения.
